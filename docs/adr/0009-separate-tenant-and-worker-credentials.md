# Separate Tenant and Worker credentials

A Tenant Master Key has tenant-wide authority and is read from standard input only for one-time `gpq worker enroll`. Remote issues a distinct revocable Worker Credential limited to Worker protocol operations. Tenant creation, key rotation, deletion, Worker management, and migration are local `gpq remote` commands; `gpq remote migrate` uses the schema-owner login, administration uses a login granted `gpq_admin`, and `gpq remote serve` uses a non-owner `gpq_app` login without `BYPASSRLS`. Public Tenant APIs authenticate with the Master Key; Workers never receive it. Master Keys are printed once and stored only as keyed hashes under `GPQ_CREDENTIAL_KEY` (32 random bytes represented by 64 hexadecimal characters).

By default, macOS stores Worker Credentials in Keychain and Windows in Credential Manager. Linux services may use systemd `LoadCredential`; otherwise Unix uses an owner-only file under the Worker state directory. On Unix, `credential_storage = "file"` explicitly selects that file store, including for headless macOS/SSH deployments, with mode `0600` in a private mode-`0700` state directory. The platform default remains unchanged and there is no automatic fallback. Configuration, command arguments, environment variables, logs, and diagnostics never carry the credential; unsafe file permissions stop startup.
