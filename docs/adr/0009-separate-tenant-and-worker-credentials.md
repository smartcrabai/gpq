# Separate Tenant and Worker credentials

A Tenant Master Key has tenant-wide authority but is passed by standard input to a Worker only for one-time enrollment; Remote then issues a distinct revocable Worker Credential limited to Worker protocol operations and stored in platform-appropriate secret storage. Tenant creation, key rotation, deletion, migration, and serving are local `gpq-remote` commands, while `gpq-worker` exposes enrollment, foreground run, diagnosis, and OS service management commands. Master Keys are generated by administration, stored only as keyed hashes, and permit temporary old/new overlap during rotation, preventing one compromised Worker from gaining public API or tenant administration authority.

Worker Credential persistence uses Keychain on macOS, Credential Manager or DPAPI on Windows, systemd credentials for Linux services, and an owner-only mode-0600 file under the state directory only for non-systemd Linux. Configuration, command arguments, environment variables, logs, and diagnostics never carry the credential, and unsafe file permissions stop startup.
