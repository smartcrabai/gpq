# Prioritize GPU utilization

Scheduling admits only Generations compatible with the Tenant, the exact pinned Model Version (canonical `ModelManifest` SHA-256), its Image or Video modality, requested image LoRA hashes, and configured shape limits. Estimated model and accelerator memory are metadata only, not admission gates. Among eligible work, the scheduler chooses overdue Generations by oldest `created_at`; otherwise it favors the Slot's resident Model, then higher priority, then older submission time. Running Attempts are never preempted for priority. The Tenant-configurable `maximum_queue_age`, defaulting to 30 minutes, prevents indefinite starvation while resident-model affinity improves utilization.
