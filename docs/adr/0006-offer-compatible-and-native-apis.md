# Offer compatible and native APIs

OpenAI-compatible requests keep their HTTP or SSE connection open while queued and cancel their Generation when the client disconnects, preserving existing SDK behavior. The supported surface is `GET /v1/models`, `POST /v1/chat/completions`, and `POST /v1/responses`, including streaming, model-supported tool calls and structured output, and multimodal image inputs by HTTP(S) or `data:` URL; Files and all other OpenAI APIs are excluded. Remote resolves external image URLs under SSRF-safe network and size limits rather than exposing Worker egress. If no capable Worker is online, OpenAI requests fail with `503 model_not_available`; busy online Workers may queue them. A separate native Generation API provides submit, status, and result operations that survive client disconnection, may wait up to 24 hours for a capable Worker, and require a tenant-scoped idempotency key; OpenAI endpoints accept the same key optionally.

Native Generation and catalog APIs use ConnectRPC unary and server-streaming methods, while Axum remains for OpenAI-compatible routes, one-shot Artifact download, and health checks. A reconnected Native event stream begins with the current snapshot and then live events; token deltas are not replayed, and discontinuity is explicit. Both public API families authenticate with the Tenant Master Key as an `Authorization: Bearer` token; public gRPC-Web exposure, WebSockets, and webhooks remain excluded.

Native creation accepts exactly one Model or Workflow alias, opaque Protobuf `Struct` backend payload, input Artifact IDs, output placement, priority zero through nine, optional seed, and an optional shortening execution timeout; modality is derived after alias resolution and idempotency travels in request metadata. Tenant settings for queue age, capacity, Artifact limits, timeout ceilings, and default priority are readable and mutable through a Master-Key-authenticated Tenant service, while credential and Tenant lifecycle operations remain local administration commands.
