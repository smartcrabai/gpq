# Run one foreground Worker everywhere

`gpq worker run` is the common foreground implementation on every supported OS. systemd on Linux, launchd on macOS, and the native Windows Service adapter wrap that same command; `gpq worker service install|uninstall|start|stop` manages those wrappers. The Worker spawns its private per-Pool inference process from the same executable using the hidden `gpq infer` role. Tenant administration, schema migration, and Remote serving are roles of that executable as well: `gpq remote ...`. There are no separately named Remote or Worker binaries.

cargo-dist ships one `gpq` executable in target-specific archives and publishes the `gpq` Homebrew formula. Standard targets are Apple Silicon macOS, x86_64/aarch64 Linux, and x86_64/aarch64 Windows. Standard builds include Metal on macOS and Vulkan on Linux/Windows; CUDA is opt-in rather than a standard release. The Linux Remote OCI image runs `gpq remote serve`.

Native compilation requires Rust, `protoc`, CMake, a C/C++ toolchain, and the target's native SDK/build prerequisites. Metal shader source is embedded at build time. At runtime, operators provide external model assets, supported GPU drivers, and OS dynamic-loader dependencies; Linux Vulkan workers additionally need the Vulkan loader. The executable includes its native inference bridge and media codecs, so Workers do not need an external model server, Python, ComfyUI, MLX, or an ffmpeg executable. Remote needs PostgreSQL but no GPU or model assets.
